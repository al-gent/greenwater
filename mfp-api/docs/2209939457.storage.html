Introduction & Purpose

This document provides a unified specification of the Cruise Data APIs. It integrates participant data, public cruise information, and maritime cruise data into one comprehensive reference. The document also incorporates recent enhancements, including enriched participant data, application-specific endpoints, and extended response schemas.

Endpoints Overview

Endpoint

Description

GET /api/v1/programme/cruise/{id}/cruiseparticipants

Retrieve list of participants for a cruise

GET /api/v1/schedule/participants/application/{workflow_id}

Retrieve participants for a specific application by workflow ID

GET /API/v1/{organisation}/schedule/{year}/{ship}

Retrieve schedule and public cruise information

GET /cruise

Retrieve cruise details including project, scientists, and ports

GET /transect

Retrieve transect (ship movement) information

GET /event

Retrieve cruise event information (mobilization, demobilization, operations)

GET /waypoints

Retrieve cruise waypoints

Errors

Code

Description

200

OK. Everything worked as expected.

400

Bad Request. The request was unacceptable, often due to missing a required parameter.

401

Unauthorized. No valid API key provided.

403

Forbidden. The API key doesn't have permissions to perform the request.

404

Not Found. The requested resource doesn't exist.

429

Too Many Requests. Too many requests hit the API too quickly. We recommend exponential backoff.

500, 502, 503, 504

Server Errors. Something went wrong on MFP end.

Notes & Known Issues

  • Some participant fields may be null due to incomplete data.

  • Chief Scientist must reflect the most recent application.

  • Use /application/{workflow_id} to retrieve the most recent application-level participant data.

  • Cruise and event data may be updated; always check ChangesHistory for audit trail.

  • Coordinates and waypoints use geoJSON conventions for interoperability.
